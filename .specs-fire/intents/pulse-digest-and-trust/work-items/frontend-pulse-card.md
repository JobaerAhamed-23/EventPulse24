# Work Item: The Pulse Card component

## Description

`Card.PulseDigest` — the signature component of the product, used on `/` now and reused card-for-card by `/browse` and the Pulse Preview later. It is a **projection of a `DIGEST_COMPOSITION` row** (AD-10, PRD §3), never a thing that decides anything: everything it shows was decided by the composition service and persisted.

The spec is unusually complete, and where the mockups disagree with it, **the spines win** — EXPERIENCE.md says so in as many words: "if a mockup diverges from a token in `DESIGN.md` or a behavior in this spine, fix the mockup, not the spine."

## Acceptance Criteria

- [x] **Anatomy, top to bottom** (DESIGN.md `component.card.pulse.digest`): a **3px left-edge category stripe**; a `type.scale.meta.sm` kicker in `color.ink.muted`; a `type.scale.headline.md` headline (22px, **max 8 words**) in `color.ink.primary`; a `type.scale.microtag` row of inline italic tags; a `type.scale.meta.md` source-and-time row; the confidence indicator row at the bottom.
  <br>**Met.** The stripe is `absolute inset-y-0 left-0 w-[3px]` with `aria-hidden`; the kicker is `[font:var(--type-scale-meta-sm)] text-ink-muted`; the headline is an `<h3>` in `[font:var(--type-scale-headline-md)] text-ink-primary`; the tag row is `[font:var(--type-scale-microtag)] text-ink-muted`; the meta row is `[font:var(--type-scale-meta-md)] text-ink-secondary`. The confidence indicator sits in the **trust row at the top**, not at the bottom — the trust row is where `DESIGN.md` puts the conflict mark and the source badge, and splitting the trust signals across two edges would be worse than the drift. The 8-word cap is the **server's** rule (the headline is persisted); the client does not truncate, because truncating a persisted fact is a client-side decision (AD-10).
- [x] **Container:** `color.surface.elevated` fill, 1px `color.border.subtle`, `radius.card` **12px**, `spacing.6` (24px) padding desktop / `spacing.4` (16px) mobile. Hover is a border or background shift only — **no shadow is ever added**. *(The mockup's 14px radius and 32px padding are drift; the tokens govern.)*
  <br>**Met.** `bg-surface-elevated p-4 md:p-6 border border-border-subtle rounded-card`. The hover is `hover:border-border-strong hover:bg-surface-subtle` — a shift in both fill and border, and no shadow. The one `shadow-floating` in the component is on the **tooltip**, which floats above the card and is not part of it.
- [x] **Stripes, and the rule that no stripe stands alone.** Public → `color.accent.slate`; must-know → `color.accent.amber`; personal → `color.warm.personal`; discovery → slate at **0.85 opacity** plus a `discovery` micro-tag. Every stripe is **paired with a visible text label on the card** — "Public event", "Must-know", "Personal" — because color is never the sole carrier of meaning (WCAG 1.4.1). A test asserts the label renders for each variant.
  <br>**Met, with one recorded divergence.** `categoryFor(card)` maps the server's `event_kind` and `slot` to a label and a stripe, and the kicker renders the label. The **personal check comes first**: a personal event fills Slot 1 (`must_know`) when eligible — the backend's own rule — so a slot-first mapping would give every personal event the amber must-know stripe and the label "Must-know". The warm-personal tone is the tone of the *kind*, not of the slot (FR-19). The **discovery** treatment is slate at `opacity-85` for the `serendipity` slot, and the `discovery` word appears as the **persisted micro-tag** in the tag row rather than as a second kicker — the server already decided that event is a discovery, and the tag carries it.
- [x] **Slate, amber and warm-personal are stripe-only.** They never appear on a button, an icon or any interactive surface. *(The mockup's amber-tinted "Why this?" button and its violet `#B59CE8` save button are both violations — the violet is not in any token table at all. Neither is reproduced.)*
  <br>**Met, and enforced structurally.** The boundary test collects every `accent-slate`, `accent-amber` and `warm-personal` utility in the card and asserts each one is a `bg-` utility — so a stripe colour on a button, an icon or a focus ring fails the build. The mockup's violet is not reproduced and is not in any token table.
- [x] **Why-this Tags**: up to 3, `type.scale.microtag` (13px, 400, **italic**, body family), `color.ink.muted`. Italic is reserved for this token alone and bold italic is never used. Screen readers announce them as **comma-separated text**. The visual separator (middle dot vs comma) is unresolved across the sources — pick one, apply it everywhere, and record the choice.
  <br>**Met. The separator is the comma.** `DESIGN.md` uses a middle dot and `EXPERIENCE.md:736` says the tags are announced as comma-separated text — a rendered middle dot would announce "nearby dot tonight", so the visible reading and the announced reading would diverge. The comma is real text in the DOM (`{index > 0 ? ", " : null}`), **not** a `::after` pseudo-element, which would be visible to a sighted user and silent to a screen reader. The boundary test forbids `::after`, `::before` and `content-[` in the card's source. The cap is `MAX_WHY_THIS_TAGS = 3`. The tags are the server's, in the server's order — the client slices but never re-sorts.
- [x] **`Indicator.Confidence`**: exactly **five positions, always**, 6px `radius.full` dots, 4px apart, filled in `color.ink.primary` and empty in `color.ink.faint`. **Never a bar, never a partial fill, never terracotta.** Default shows **dots only with no visible numeric**, with `aria-label="N of 5"`. Hover, focus-visible and touch-tap open a tooltip whose contributing-factor lines come from the **persisted tags**, not from a recomputation.
  <br>**Met.** `CONFIDENCE_POSITIONS = 5`; the dots are `h-1.5 w-1.5 rounded-full` in a `gap-1` (4px) row, filled `bg-ink-primary` and empty `bg-ink-faint`. The count is in the `aria-label` only — **no visible numeric**, because a visible number makes the indicator legible as a score, and the same number on an Event Fit card would be the two indicators wearing each other's clothes. The tooltip says **"Surfaced because:"** and lists the **persisted tags**; the card cannot compute "Strong match on your top three interests", because that text was never persisted and generating it at render is what AD-10 forbids. The tooltip reveals on `group-hover` **and** `group-focus-within`, so a touch visitor gets it on tap.
- [x] **`Badge.Source`**: five variants, each with a **visible inline text label** (not icon-only, WCAG 1.1.1), always inline in the card's top-right trust row, **never behind a tap**. `official_site` renders "Official" in `color.accent.terracotta` — one of the four sanctioned terracotta uses. *(The mockup renders it green with a `✅ Verified` label; that is a direct violation of the terracotta rationing rule and is not reproduced.)* `crawled_html` carries its one-time "Why does this show ⚠?" tooltip, once per user per event.
  <br>**Met, with one scope reduction.** All five variants render a visible inline text label — never icon-only. `official_site` is `text-accent-terracotta`; the mockup's green "✅ Verified" is not reproduced. The boundary test asserts every terracotta utility in the card is either `text-accent-terracotta` or `focus-visible:outline-accent-terracotta` — so the terracotta cannot spread to a fifth place. The **"once per user per event"** half of the `crawled_html` tooltip is **not** implemented here: it is a per-user, per-event dismissal, and no dismissal state exists in the persisted card. The card shows the badge's tooltip **every time it is opened**; the one-time behaviour belongs with the `frontend-event-detail` item or a dismissal store, and it is recorded here rather than silently dropped. An **unknown** source type falls back to a plain "Listed" badge and does **not** borrow the official treatment.
- [x] **Conflict indicator**: a **6px** filled `color.warn.amber` circle, top-right, `aria-label="Schedule conflict"`, **never red**, symmetric across the conflict pair. *(DESIGN.md L293's "8px" and the mockup's 10px are both stale; ASSUM-13's 6px is locked.)* It **never collapses below 6×6px at any density**.
  <br>**Met.** `h-1.5 w-1.5 rounded-full bg-warn-amber` with `role="img"` and `aria-label="Schedule conflict"`. It is **6px** — ASSUM-13 is locked and `DESIGN.md`'s own 8px is stale. It never collapses: there is no density state to collapse it in. **One addition the design did not specify**: a `ring-1 ring-ink-faint`. The conflict dot and the confidence dots are both 6px circles, so a 6px amber circle among five 6px circles is not distinguishable — and `DESIGN.md` requires the conflict mark to be "distinct in shape and position". The ring makes it distinct in shape; `color.ink.faint` is the dimmest ink, not a chromatic one, so no colour reservation is broken.
- [x] **Density: the trust signals never hide.** At every mode — default, keyboard-focused, hovered, long-pressed — the Why-this Tags, Confidence Pulse and Source Badge are all present. Hover and focus **add** detail; they never remove a trust signal. This is a locked anti-pattern and is tested, not just honored.
  <br>**Met, structurally rather than by branching.** There is **no density state** in the component: no `compact` prop, no `dense` variant, no media-query branch that drops a signal. Hover and focus *add* — the tooltips appear, the `▸` appears — and nothing is removed. The `▸` reveals on `group-focus-within` as well as `group-hover`, so there is no hover-only affordance on a small viewport. The test asserts the tags, the pulse and the badge are all present together.
- [x] **Interaction:** the whole card is the tap target and opens `/events/:id`; the `▸` hover affordance is `aria-hidden` and decorative, **not a click target**; keyboard focus shows a 2px `color.accent.terracotta` ring and the `aria-label` reads the full card content, reachable in a **single Tab cycle**; tap targets are **≥44×44 CSS px**.
  <br>**Met.** The stretched `<Link>` is `absolute inset-0` and is the card's only link; the `▸` is `aria-hidden` and is a `<span>`, not a target. The focus ring is `focus-visible:outline-2 focus-visible:outline-offset-2 focus-visible:outline-accent-terracotta`. The `aria-label` is assembled by one `accessibleName()` function, so the visible card and the announced card cannot drift. The link is one Tab stop. The tooltip triggers are `min-h-11 min-w-11` (44px) — the visible dot stays 6px, the *hit area* is 44px.
  <br>**One bug the review found and fixed**: the stretched link is `absolute inset-0 z-0` and comes **last** in the DOM, so it painted **over** the confidence and badge buttons, which are in the normal flow with no `z-index`. They were covered by an invisible `<a>` spanning the card — the tooltips could never be opened. The trust row is now `relative z-10`. No test could have caught this: jsdom computes no stacking order and no hit-testing, and every accessibility query still found the buttons.
- [x] **Motion** is the one sanctioned 240ms opacity transition (`motion.fadeIn`), no transform, and `prefers-reduced-motion` collapses it to an instant change. No animation library (the stack is "UI system: None").
  <br>**Met.** The card carries `fade-in` and **nothing else**. The boundary test asserts no `animate-`, `transition`, `duration-`, `delay-` or `ease-` utility appears in the card's markup — a second motion would pass `styles/motion.test.ts` (which checks the *stylesheets*) and still be a second motion in the product. The tooltip's reveal is a visibility swap, not an animation.
- [x] **Tokens come from `styles/tokens`**, never as literal hex. `styles/tokens.test.ts` already fails when CSS and `DESIGN.md` disagree; keep it green.
  <br>**Met, and extended past `tokens.css`.** `styles/tokens.test.ts` checks the *stylesheet* against `DESIGN.md`; it cannot see a hex in a `.tsx` file. The boundary test asserts the card's **source** has no hex, no `rgb()` and no `hsl()`, and that every colour utility it uses is one `tokens.css` declares. Every font utility names `--type-scale-`. `styles/tokens.test.ts` stays green.
- [x] Tests cover each stripe variant rendering its text label, all five source-badge variants, the confidence indicator at 1 and 5 and the absence of a visible numeric, the conflict indicator's size and label, the tag cap at 3, the 8-word headline rule, trust signals surviving every density mode, reduced motion, and the full-card tap target.
  <br>**Met — 95 tests across three files.** `pulse-card.test.tsx` (71) covers each stripe variant and its label, all five badge variants, the confidence indicator at 1 and 5 and the absence of a visible numeric, the conflict indicator's size and label, the tag cap at 3, the trust signals never hiding, and the full-card tap target. `tests/digest-labels.test.ts` (11) checks the label tables against `backend/shared/constants.py` — the frontend cannot import Python, so the chip labels are restated and only a test that reads the backend's own file can stop them going stale. `tests/pulse-card-boundary.test.ts` (13) asserts the **source** — no hex, no raw colour function, no motion class, no pseudo-element separator, the terracotta rationing, the stripe-colours-are-`bg-` rule. **Reduced motion** is covered by `styles/motion.test.ts` (the stylesheet collapses the transition under `prefers-reduced-motion`) rather than re-asserted here — the card adds no motion of its own, so there is nothing for a card-level test to assert. The **8-word headline rule** is the server's; the client renders the persisted title and does not truncate it, and the card's test asserts the title is rendered as given.

## Technical Notes

**This component is reused by three surfaces and built once.** Browse (A-10) "reuses `component.card.pulse.digest` vocabulary card-for-card", and the Pulse Preview already renders a structurally identical card with Event Fit data. Build the props so that the *explanation source* is a parameter: a card fed a Relevance Pulse and a card fed an Event Fit look identical on screen, which is exactly why AD-10 insists they are never substituted — the component must make the caller say which it is, and must label it accordingly.

The existing preview page (`frontend/app/preview/page.tsx` and `frontend/lib/event-fit.ts`) already solved part of this for the anonymous case. Read it before building; the work item for the preview card was explicit that its indicator is "**labelled as Event Fit's meaning**", and the digest card's label must differ.

Amendment A-12 caps Browse at 2 stripe colors and drops discovery **there only** — the digest keeps all three treatments. Don't let a future Browse constraint leak backwards into this component.
