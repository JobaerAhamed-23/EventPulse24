## Git Workflow

- **Commit Style**: Conventional commits (feat:, fix:, chore:, docs:, refactor:, test:)
- **Branch Strategy**: Feature branches named `PROD-NNNN-<short-slug>`, merged via pull request
- **Main Branch**: main is always deployable

## Code Review

- All changes require pull request review
- At least one approval required before merge
- No self-merging to main
- Security-sensitive changes (auth, credentials, billing, schema routing, retention) require additional review
- Migrations: forward-only, one per PR, reviewed for AD-3 schema routing and AD-15 retention declaration

## CI/CD

- **Platform**: GitHub Actions
- All PRs must pass CI checks before merge: tests, `import-linter` contracts, `manage.py check`, OpenAPI client regeneration, `axe-core` on PRD §11.5 surfaces
- Automated tests run on every push
- Main branch deployments are automated (Vercel for frontend; always-on Python host for API/worker)
- Preview environments never send real email and never write to the real Source Registry

## Security Policies

- **No secrets in code** — config is validated once at startup via pydantic-settings; secrets live in the platform secret store only
- No PII in logs — redaction enforced at the logger adapter's allowlist (AD-13)
- Every calendar credential (secret ICS URLs, OAuth tokens) encrypted at rest with the application-level key (AD-18)
- Ingested source content is untrusted input — never executed, never rendered raw, always delimited in prompts (AD-9)
- Dependencies must be from trusted sources; vulnerabilities addressed within SLA
- No credentials, API keys, or tokens in source control

## Documentation

- The API contract is the generated OpenAPI schema (AD-19) — every endpoint appears in it
- Breaking changes require migration notes
- README kept up to date with setup instructions; `runbook.md` is the on-call first stop
