## Decisions
- **D1 - the detail route key**: The UUID (id), not the slug (The AC names {id} twice and lists id in the response schema. The slug belongs to the later FR-26-28 page intent; the response also carries slug so the page route /events/{slug} is buildable without a second lookup.)
- **D2 - what "upcoming" means**: start_time_utc >= now, where now is the request time (The AC says upcoming published events. A past event disappears from the list.)
- **D3 - ordering**: start_time_utc ascending, then id ascending as the tiebreak (The natural order for an events list, and the id tiebreak makes the order total, so pagination can neither repeat nor skip an event.)
- **D4 - pagination shape and default size**: An explicit envelope {items, page, page_size, total, has_next}; page defaults to 1, page_size to 20, capped at 100 (Ninja built-in pagination gives {items, count} only, so the frontend would have to derive the rest. The envelope is explicit in the OpenAPI schema, which is what AD-19 wants.)
- **D5/D6 - cancelled and postponed events**: Both are listed, carrying their status (The AC names exactly two exclusions (in_review and superseded). A cancelled event is still a public fact, and a status field that could only ever be scheduled would not be worth carrying.)
- **D7 - the tz_review_pending flag**: A boolean tz_review_pending field alongside status (The AC asks for the flag on a tz_review_pending event; it is what the frontend needs to show "venue time approximated".)
- **The read interface hands over plain data, not model instances**: A frozen dataclass PublicEvent (Deviation from the plan, and stricter: the caller never holds a reference to apps.ingestion.models, so the import wall holds without either side knowing the others models.)
- **The worker-not-api contract was tightened**: config.api added to forbidden_modules (config.api assembles the app routers, so it reaches apps.*.api transitively. The planted-violation test was updated to expect two broken contracts instead of one.)
