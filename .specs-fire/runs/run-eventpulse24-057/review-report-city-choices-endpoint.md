## Findings

### 1. [Architecture] The route reached into a sibling module's private helpers — FIXED

**Files**: `apps/catalog/public_surface.py` (new), `preview_api.py`, `cities_api.py`

The new route needs three things the preview route already had: `_client_ip`,
`_throttle_key`, `_cacheable`. The first draft imported all three from `preview_api` —
underscore-prefixed names, across modules. That is a smell on its own, and the next person
adding a public route would copy it.

The alternative the codebase seemed to suggest was duplication: `apps/identity/api.py`
keeps its *own* `_client_ip` rather than sharing one. But that is a different app and a
different surface, and `_client_ip` is twenty lines of security-critical logic — a third
hand-maintained copy is a third place for `TRUST_FORWARDED_FOR` to be forgotten, and the
failure mode is silent (any caller mints a fresh throttle bucket per request).

Extracted to `apps/catalog/public_surface.py`: one module, one rule each, for the two
routers of the one public surface. `preview_api` imports them under their old private names,
so nothing that referenced them still resolves differently. `identity`'s copy is left alone
and the new module's docstring says why.

**Risk**: low. A pure move; `tests/api/test_preview_api.py` (39 tests) passes untouched.

### 2. [Testing] An architecture guard pinned a count instead of checking a property — FIXED

**File**: `tests/architecture/test_preview_anonymity.py`

`test_the_public_preview_router_has_no_auth_and_no_session_dependency` asserted
`len(public) == 1` before checking that one router's `auth`. The count was incidental —
there happened to be one public router — but the *property* is "no router on `/public` has
an auth dependency".

As written, adding a second public router **failed the test instead of being covered by
it**: the guard broke at exactly the moment it had more to guard. Changed to assert the
list is non-empty and then check every router in it. The new route is now covered by a test
that did not have to be written for it.

**Risk**: none, and the guard is strictly stronger.

### 3. [Testing] A test of mine could not fail — FIXED

**File**: `tests/api/test_cities_api.py`

`test_it_does_not_spend_the_previews_budget` exhausted the new route's limit and then
asserted `/api/public/preview/cities` still answered. But that route's throttle scope is
`preview:cities`, while the collision a scope mistake would cause is with
`/api/public/preview`, scope `preview`. **The mutation check caught it**: changing the new
route's scope to `preview` left all 17 tests green.

Parametrized over both preview routes. The mutation is now caught, and the comment in the
test says why both are listed so nobody trims it back to one.

### 4. [Testing] An assertion of mine rested on today's data — FIXED

**File**: `tests/api/test_cities_api.py`

`assert labels != sorted(labels)` was meant to show the order is a casefold sort rather
than a byte sort. It failed, correctly: every current label begins with an uppercase letter,
so the two orderings agree. Had the catalog happened to contain a lowercase-initial city it
would have passed — and silently become meaningless the day that city was removed.

Removed, with a comment explaining that the distinction cannot be drawn from this endpoint's
data and that the mechanism is pinned where it can be: `choices()` sorting with
`key=str.casefold`, asserted in `tests/domain/test_city_catalog.py`.

## Deliberately Not Changed

- **`list_supported_cities` keeps its name and every line of its behaviour.** The temptation
  was to rename it to something like `list_preview_coverage` now that the confusion is
  named. But it is called from `digest_preferences` and `preview_api`, it is in a published
  read interface, and a rename would put churn in this diff that has nothing to do with the
  endpoint. The docstring now does the work a rename would have.
- **No `ETag` on the response.** `Cache-Control` plus `stale-while-revalidate` is what this
  resource needs; an ETag would add a conditional-request path to an endpoint whose whole
  body is smaller than most of the pages that link to it.
- **The response carries no catalog version.** Plausible and currently useless: nothing
  consumes one. `CityChoicesOut` is an object rather than a bare array precisely so that one
  can be added without breaking a client.
- **The endpoint does not filter to cities that have events.** That is the entire point of
  the item, and `test_a_city_with_no_events_is_still_offered` is the assertion that says so.

## Security

Modest surface, and all of it inherited. No session, no cookie, no `personal` read — checked
behaviourally (identical bytes) and structurally (the source contains neither `request.user`
nor `personal`). The response is a projection of a frozen module-level tuple, so there is no
user input reaching anything: the route takes no parameters at all. The throttle key is the
caller's IP and a fixed literal scope, never anything the caller controls, and the IP is
never logged or stored (AD-13). A refused request is explicitly `no-store`, so a shared
cache cannot lock out everyone behind it.

## Architecture

The route is in the AD-5 surface list (`test_no_direct_writes`) and the AD-11 request-module
list (`test_digest_composition_separation`), both hand-maintained and both updated with a
comment saying why this file belongs. It writes nothing, opens no transaction and runs no
query — about as close to AD-11's ideal shape as a request handler gets.

Two routers on one prefix is the pattern `/settings` already uses with five. The import
contracts are unaffected: `apps.catalog` importing `domain.city_catalog` is a layer reading
downward.
