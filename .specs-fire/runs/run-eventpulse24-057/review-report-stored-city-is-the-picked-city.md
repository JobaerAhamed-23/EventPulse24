## Findings

### 1. [Correctness] `_canonical` became dead code — FIXED

**File**: `apps/personalization/services/digest_preferences.py`

The plan said `_canonical`'s `raise ValueError` invariant guard would stay, re-pointed at
the catalog. It did not stay: `resolve_home_city` now does the lookup itself and returns
`row.name` directly, so **nothing calls `_canonical` any more**. It was a helper whose
only caller had been folded into the function above it.

The coverage report is what surfaced it: `digest_preferences.py` was at 97% with exactly
one uncovered line in the module — `_canonical`'s `return row.name`, the success path of
a function nobody reaches. The `raise` branch was covered, because the test called
`_canonical` directly; the *useful* line was not.

**Deleted**, with its test. The invariant it guarded — *a stored city is always a city the
catalog holds, in the catalog's spelling* — is now enforced at the single point that
stores a city, and pinned over the whole dataset by
`test_the_stored_city_is_always_a_city_the_catalog_holds`. The fourth mutation in the test
report is that test's proof: replacing `row.name` with the caller's spelling fails 170
tests, the new one among them.

**Risk**: none. A private function with no callers.

### 2. [Behaviour] The seed's fictional city was refused — FIXED

**Files**: `apps/personalization/services/{digest_preferences,onboarding}.py`,
`apps/personalization/models.py`, `config/management/commands/seed_browse_catalog.py`

The local dev seed writes **"Fixtureville"** — a fictional city for a walk-through, not
in the catalog and never able to be. Under the new rule its write was refused, and **26
tests** in `tests/config/test_seed_browse_catalog.py` failed.

The tempting fix is to put "Fixtureville" in the catalog. That is wrong: it is not a place
a reader may choose, and putting it there would make the picker offer a city that does
not exist — the exact thing the catalog exists to prevent.

The other tempting fix is to bend the seed's city into a real one. That is also wrong:
the seed's venues, its events and its accounts' city would then disagree, and the Browse
surface the walk-through exists to show would be empty.

The fix is to say what the seed **is**. The seed is the **server choosing** a city, with
no reader in the story at all — which is exactly the situation that already exempts the
fallback from the catalog check. So:

- `resolve_home_city` gained a `SOURCE_SEED` branch: the value is stored **verbatim**,
  because the server chose it. The length bound still applies.
- `set_digest_preference` gained a `city_source` parameter, **defaulting to
  `SOURCE_CHOICE`** — every browser path that sets a city is a reader picking one, so the
  default is the common case and the parameter is the exception.
- `DigestPreference.CitySource` gained `SEED`. The four originals describe how a
  **reader's** city arrives; the fifth does not, and the model's docstring now says so.
- The seed passes `city_source=SOURCE_SEED`.

**The migration touches no rows.** `city_source` is a `CharField` with `choices`, and
Django does not enforce choices at the database level, so `0018` is an `AlterField` on the
Python-side vocabulary and nothing else. The migration's docstring says exactly that, and
says what the reverse does.

**Risk**: low, and contained. The new source is reachable from exactly one call site, the
seed.

### 3. [Gap] "Montgomery" was not in the curated catalog — FIXED

**File**: `domain/city_catalog.py`

The project's own local seed registers **Montgomery** — `config/local_feeds.json` names it
as the source's city, and `config/local_feeds.fixtures.json` fills it with venues. It was
**not in the curated catalog**.

Under the old rule that was harmless: the city was stored as the fallback and the surface
showed New York City. Under this item's rule it would be **refused**, and — because the
frontend picker still reads `preview/cities` (item 8 rewires it) — the picker would offer
a city the server answers with a 422.

The catalog gained the row: `("Montgomery", "", "", "America/Chicago")`.

- **No region qualifier**, because the string the seed's venue and its source already
  use is plain `"Montgomery"`. A qualified `"Montgomery, AL"` would key as
  `("montgomery", "al")` and resolve to nothing — a *different* city, and the stored
  string would not match. The label is "Montgomery, United States", the same shape as
  "Brooklyn, United States", which is the same case for the same reason.
- **`America/Chicago`**, not the country's `America/New_York` default: Montgomery is in
  Central Time.

The catalog's own whole-dataset invariants hold over the new row — `tz` canonical, `name`
round-trips through `split_region`, no identity or lookup-key collision, no duplicate
label — and `tests/domain/test_city_catalog.py` (39 tests) passes untouched.

**Every city the repository mentions is now in the catalog**, checked over every JSON file
under `backend/config/` and `backend/tests/fixtures/`: `Montgomery` resolves; the only
other is "Fixtureville", which is the seed's fictional city and is handled by finding 2.

## Deliberately Not Changed

- **No migration of the existing `city_source="fallback"` rows.** The brief forbids it and
  the reasoning holds: nulling them would push a surprise empty Browse onto people who
  never asked for one, and `citySourceNote()` already labels them honestly. They repick
  whenever they like — and now the pick sticks. `test_a_pick_replaces_a_fallback_row_with_the_picked_city`
  names the consequence, and `test_an_existing_fallback_row_is_left_alone` names the
  guarantee.
- **The frontend is untouched.** `home-city.tsx` already replaces its optimistic value with
  the server's answer and renders `response.error` verbatim, so a 422 shows its message
  and reverts — no change is needed for this item to be observable. Its stale docstring
  (which still claims the choices come from `preview/cities` and that the server rewrites
  a city silently) is **item 8's** work; that item depends on this one, and rewiring the
  dropdown to `/api/public/cities` is where the docstring's claims stop being true.
- **`store_fallback_city` and `backfill_home_cities` keep their behaviour**, including the
  backfill's idempotency. The fallback is still not catalog-checked, for the same circular
  reason as before: the fallback is by definition a city the catalog may not hold.
- **`resolve_home_city`'s signature is unchanged**, `now` included. The catalog does not
  change with the clock, so `now` is not read — but removing it would churn every caller
  for no gain, and `set_home_city` has a `now` it needs anyway. The docstring says so.

## Security

The refusal's channel is the only new surface, and it is narrow by construction.

- **The refused city is echoed in `details["rejected_city"]`**, and that is defensible:
  the reader sent it, over their own authenticated session, and needs to be told which
  value was refused. Echoing a value back to its sender is not disclosure.
- **The message does not quote it.** The message is for a person and stays calm; the value
  is machine-readable data for the client that needs to re-select. Two audiences, two
  places — asserted separately, because a test that only checked the message would pass
  if the value were missing from `details`.
- **The audit row stays silent.** AD-13 keeps the city out of the audit log and out of
  the log sink; the audit row says *that* the city changed and never *which*. Asserted
  with **both halves** — the city is absent from the details, *and* the details are not
  empty — so an empty details dict cannot pass for the right reason.
- **The refusal writes nothing**: no `DigestPreference` row, no audit row, no
  recomposition. It is raised **before** the transaction opens, so there is nothing to
  roll back.
- **`UnknownHomeCityError` is a `ValidationError`**, so `config/errors.py` maps it to
  **422** with the project's one error shape `{code, message, details}`. No error-handler
  wiring changed, and no new mapping was added.

## Architecture

The module now imports `domain.city_catalog` instead of `apps.ingestion.services.preview_read`.
That is the point of the item: it removes the last dependency on the preview's coverage
answer from the place that decides which city a reader may have. `domain.city_catalog` is
a `domain` module, and AD-2 points inward — `apps` may import `domain`. The
`models-ingestion` contract protects the *models* module, not the services. `lint-imports`
confirms: **21 contracts kept, 0 broken**.

`set_digest_preference`'s new `city_source` parameter defaults to `SOURCE_CHOICE`, so
**every existing caller is unchanged** — the sign-up path, the API edge, the onboarding
command. Only the seed names a different one, and it names it explicitly.
