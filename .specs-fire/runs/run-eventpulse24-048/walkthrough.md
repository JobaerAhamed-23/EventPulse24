**There is no number on that page that did not come from `shared/constants.py`.** That is
the property the whole run is built around, and it is enforced by a test rather than by
discipline (below).

## The decisions that shaped it

**The weights are served, never duplicated.** A weights table typed into TypeScript would
be a second source of truth on the one screen whose entire job is that there is exactly
one, and it would drift from the backend silently. That is FR-22's failure mode exactly.

**Decimals cross the wire as strings.** `Decimal("0.85")` is not the float `0.85`, and the
whole of `domain/ranking.py` turns on that because an exact boundary decides a dot count. A
JSON number hands the browser a double on the page that exists to let a reader check the
arithmetic.

**The page never sums the weights.** The total is the server's. A floating-point sum
rendered as `1.0000000000000002` would discredit the very thing the page demonstrates.

**There is no worked example.** Tempting here, and wrong for the same reason: an example
score computed in JavaScript could land on the wrong side of a boundary, on the one page
that exists to prove the arithmetic is sound. The page gives the terms, the weights and
the boundaries; the reader does the multiplication — which is precisely what FR-22 says
they are entitled to do.

**Two new constants, because FR-22 needs a date nothing held.**
`RANKING_WEIGHTS_AMENDMENT = "ADR-0025"` named the engineering record but not the published
amendment or when it last moved. `RANKING_WEIGHTS_AMENDMENT_ID = "A-25"` and
`RANKING_WEIGHTS_AMENDMENT_DATE = date(2026, 11, 19)` are now pinned — and the constants
test asserts the ID appears in **both** ADR-0025 and the PRD's FR-22 section. **The page
cannot show a stale amendment without CI going red.**

**The nav row says "Privacy", described as "How your Pulse is ranked."** Your call at the
checkpoint. The route matches the IA EXPERIENCE.md §2 row 9 specifies; the description is
honest about the single section that exists.

## Four things the review and the test suite caught

**1. `gap-10` emitted no CSS at all.** `tests/spacing-scale.test.ts` failed on it. The
project resets Tailwind's spacing multiplier and declares only 0/1/2/3/4/6/8/12/16/20/30,
so an off-scale step produces **nothing** — no warning, no error, just sections with no gap.
Seventy-nine had shipped before that test existed. Changed to `gap-12`.

**2. Two architecture guards rejected the new `*_api.py` — correctly.**
`test_no_direct_writes.py` counts surface files and `test_digest_composition_separation.py`
keeps a `REQUEST_MODULES` tuple, because *"a surface file missing from this list is exempt
from AD-5, and nothing else would catch it."* Registered in both, with a note on why a
query-less read still belongs: **a read that is exempt today is a write that is exempt
tomorrow.**

**3. A comment in my own code was false.** `_WEIGHTS`'s docstring claimed a key mismatch
would be caught "at import-adjacent time". It would not — the lookup is inside the view, so
a mismatch would have been a **500 at request time**, and a weight with no label would have
been worse: silently omitted, leaving four terms that do not sum to the total printed beside
them. Rather than soften the comment, the check now exists: an import-time set comparison
that names both offending keys and stops the process from starting.

**4. The component hard-coded the scale's size.** `"○".repeat(5 - bucket.dots)` — not a
weight, so the guard did not catch it, but the same mistake in miniature. Now
`buckets.length - bucket.dots`.
