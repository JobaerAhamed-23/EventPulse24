# Implementation Plan: FR-22's transparency promise has no surface

## Approach

**A real build, unlike the two runs before it** — a new authed route, a new read endpoint,
two new constants, and tests. FR-22's own testable consequence is unbuilt:

> Settings → Privacy → "Ranking algorithm version" shows the current weights and the
> last-amendment date.

Nothing in `frontend/` renders a formula today, so no user is shown a wrong one — the
promise is simply unkept. This run keeps it.

**The weights are served, never duplicated.** `shared/constants.py` holds
`RANKING_WEIGHT_*`; the backend projects them onto the wire; the page renders what it is
given. A second copy of those numbers in TypeScript would be a second source of truth on
the one page whose entire job is that there is only one — and it would drift silently,
which is the failure FR-22 exists to prevent.

## Technical Details

### Why two new constants

FR-22 requires the **last-amendment date**, and nothing in the codebase holds it.
`RANKING_WEIGHTS_AMENDMENT = "ADR-0025"` names the ADR but not the PRD amendment ID or
when it was last moved. Parsing a markdown document at request time would be worse than a
constant in every way, so:

```python
RANKING_WEIGHTS_AMENDMENT = "ADR-0025"          # existing
RANKING_WEIGHTS_AMENDMENT_ID = "A-25"           # new — the PRD amendment
RANKING_WEIGHTS_AMENDMENT_DATE = date(2026, 11, 19)  # new — when it last moved
```

**And they are pinned the same way the weights are.** `test_constants.py` already reads
ADR-0025 and asserts every weight appears in it, and run 047 extended that to the PRD's
FR-22 section. This run adds the amendment ID to both checks — so a future amendment that
changes the ID in the docs but not the constant (or the reverse) fails CI. **The page
cannot show a stale amendment without a test going red.**

### The endpoint

`GET /api/settings/ranking`, on the `settings` router with `auth=current_user` — the same
auth as every other settings endpoint, because the surface is authed per EXPERIENCE.md §2
row 9. The response:

```json
{
  "terms": [
    {"key": "interest_overlap",   "label": "What you picked",        "weight": "0.35"},
    {"key": "source_reliability", "label": "How reliable the source is", "weight": "0.25"},
    {"key": "recency",            "label": "How soon it starts",     "weight": "0.20"},
    {"key": "city_match",         "label": "How near it is",         "weight": "0.10"},
    {"key": "confidence",         "label": "How sure we are of the details", "weight": "0.10"}
  ],
  "total": "1.00",
  "buckets": [{"dots": 5, "min_score": "0.85"}, ...],
  "boundary_rule": "lower",
  "amendment": {"id": "A-25", "record": "ADR-0025", "date": "2026-11-19"}
}
```

**Decimals cross the wire as strings.** FR-22's boundaries are exact and the codebase is
emphatic that a float `0.85` is not `Decimal("0.85")`. A JSON number would be parsed into a
JavaScript double on the very page whose purpose is that the arithmetic checks out.

**The labels are the server's vocabulary**, the same rule `INTEREST_CHIPS` and the category
keys already follow: the client never owns a list of formula terms and can never display a
term the server does not recognise.

### The page

`/settings/privacy`, server component, the exact shape `/settings/taste` uses: session
check → `homeRoute` redirect → `SettingsStates` on unavailable → `AppShell` + `SettingsNav`
+ header + content. A failed read renders the settings error state, **not an empty
formula** — a blank transparency page is a worse answer than "unavailable".

**No worked example with client-side arithmetic.** Tempting on this page, and wrong: a
computed example in JavaScript floats could land in the wrong bucket on the one page that
exists to prove the arithmetic. The page shows the terms, the weights and the boundaries,
and lets the reader do the multiplication.

### One decision that needs your call — see the checkpoint

The route is `/settings/privacy`, but this run builds **only** its ranking-transparency
section. EXPERIENCE.md §2 row 9 also commits that route to a data inventory, export
(FR-52), deletion, training opt-out, the A-14 geo-IP consent toggle and the A-13
amendment-history timeline. A nav row labelled **"Privacy"** may over-promise. The
alternative is to label the row for what is behind it. Presented at the checkpoint.
