## Acceptance Criteria Validation

- ✅ **Commands** `register_source`, `update_source`, `pause_source`, `resume_source`, `record_tos_review` and `register_venue` exist, plus `set_venue_timezone` (plan R7). Each one:
  - validates its input (parametrized invalid-field tests name the failing `loc`)
  - runs in `transaction.atomic(using=CATALOG)`. Under `transaction=True`, with `write_audit` patched to raise, no Source is left behind and an update keeps its old values.
  - writes an `IngestionAuditEntry` with the actor ID, asserted for every command
- ✅ **FR-17 hierarchy guard:**
  - Registering or switching to crawl without an approved review raises `CrawlNeedsTosReviewError`, and the tests assert no Source, TosReview or audit row is written.
  - A rejected review is refused too.
  - The ingest guard `ensure_can_ingest` refuses paused sources and unapproved crawl sources.
  - crawl → api needs no review (`test_update_source_crawl_to_api_needs_no_review`).
- ✅ **Cadence defaults:**
  - RSS = 4h, asserted as a literal `timedelta(hours=4)`.
  - Every method gets `DEFAULT_INGESTION_CADENCE[method]`, and the parity test checks the map covers exactly the `AcquisitionMethod` values.
  - The 15-minute floor is enforced.
- ✅ **`tos_status` reset on a method change**, in the same transaction. The invariant test walks rss approve → api → rss → reject → approve → crawl(with review) → rss. The rss → api → rss step proves an old approval doesn't revive (plan R3). Host changes reset it as well (R4).
- ✅ **Audit actors:** admin rows have `actor_kind = user`, `actor_id = request.user.pk`, `actor_label = ""`. No username or email reaches `catalog`; the name is only looked up from `personal` for display.
- ✅ **Django admin:**
  - The Source list has method, status, `tos_status`, `tz_coverage`, `last_ingested_at` and the stale flag, plus search and filters.
  - Venues are listed.
  - Events and state changes are read-only: add returns 403, change pages have no save button, and a POST returns 403.
  - Saves go through commands; the audit row proves it, because `obj.save()` writes none.
  - Delete returns 403 even for a superuser, `delete_selected` is not offered, and `delete_model`/`delete_queryset` raise.
- ✅ **Staff user ID by value**, with no FK (OQ-8): `actor_id` and `reviewed_by_id` are UUID columns.
- ✅ **Auditable:** the audit changelist shows when (`at`), who (the username, or "<job> (system job)"), the action and the target. The detail page resolves the username too.
- ✅ **No direct writes:** the AST scan of all 13 surface modules (`apps/*/admin.py`, `apps/*/api.py`, `config/api.py`) finds no write calls. Planted sources prove each of the 8 write names is caught, and that `refresh_from_db`, `register` and command calls are not.
