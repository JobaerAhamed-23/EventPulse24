# Implementation Plan: AD-3 Schema Router Spike

Implements the approved design (revision 3). The design's decisions D1–D13 are not repeated here; this plan fixes **order, file contents and verification**.

## Approach

Build bottom-up so every layer is verified before the next depends on it:

1. **Database first.** Make the init script per-database and idempotent, add the test template and `CREATEDB`, and apply it to the **running** container with the new `make db-init`. No reset; the dev DB keeps its (empty) state. `db-check` gains template/`CREATEDB` checks.
2. **Config.** `env.py` (role + optional owner URL), `shared/db.py`, `databases.py`, `db_router.py`, `checks.py` + `apps.py`, settings wiring, `identity.User`.
3. **Real migrations, in the design's order.** Generate `identity/0001`, then `make fmt-backend`. Then (a) run `migrate` as the **runtime** role on the still-unmigrated dev DB and confirm it is **denied**, (b) `make migrate` as owner, (c) confirm the tables landed in the right schemas.
4. **Test harness.** `settings_test.py`, `tests/conftest.py` (both aliases always set up, guarded), probe apps + migrations (documented command, then `make fmt-backend`).
5. **Wall tests**, then the full suite, lint, `manage.py check`. Also run **a single wall test file on its own** and confirm the dev DB gained no probe tables (regression check for plan-review #1).
6. **Hand-offs.** Standards, work-item criteria 1/2/4, ci-pipeline notes, spine OQ-8, docs + README, run.md Decisions.

## Technical Details

- **Why the conftest sets up both aliases itself:** Django links `catalog` to the test DB only if `catalog` is among the aliases being set up (`get_unique_databases_and_mirrors(aliases)`), and pytest-django derives that list from the *selected* tests. A partial run would leave `catalog` on the dev DB, and the owner-role `migrate --database=catalog` would then write probe tables into `eventpulse24`. The override always sets up both, and the NAME guard turns any future regression into a hard stop rather than a dev-DB write. If no selected test requests the DB, the fixture isn't used and nothing connects.
- **`serialized_aliases=set()`:** the suite doesn't use `serialized_rollback`, so no alias is serialized (faster setup). Documented in the conftest.
- **Router raise vs Django internals:** Django's migration recorder queries with `.using(alias)` and never calls the router, and the contrib apps only route mapped models. Any surprise is fixed by mapping the app, **not** by softening the router.
- **Env precedence:** pydantic-settings prefers process env over `.env`, so the Makefile's inline `DJANGO_DB_ROLE=owner` wins over `.env`'s `runtime`.
- **`make db-init`** runs the script inside the container (`docker compose exec -T postgres sh /docker-entrypoint-initdb.d/01-schemas-and-roles.sh`) using the container's own env, so passwords come from compose, as on first boot.
- **Flushes:** `transaction=True` tests truncate tables on both aliases afterwards; Django computes the table list per alias through `allow_migrate`, so each flush stays in its own schema.
- **Mac:** after pulling, run `make db-init` then `make migrate` (documented); `make doctor` already flags the new `DJANGO_DB_ROLE` key.
