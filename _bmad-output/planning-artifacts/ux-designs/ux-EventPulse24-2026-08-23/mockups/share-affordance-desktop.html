Same affordance at the surface's own specified weight. The behaviour does not change with the weight — only the chrome does.

A–D Four outcomes — and one of them is silence the control makes claims; they must be true
A · shared Shared.

The native Web Share sheet accepted it. The user picked the app; the app did the rest.

B · copied Link copied.

No Web Share API. The clipboard took it — and the control says which, because "I copied it" and "I shared it" are different claims.

C · failed Couldn't copy the link. Try again.

Neither happened. Never claims a copy that did not occur — the one thing this confirmation must not do.

D · dismissed (says nothing)

A designed state, not an omission. The user closed the sheet. That is their choice, not an error, and reporting it as one would be a lie about their own action.

One URL, one builder

https://eventpulse24.com/events/designing-for-calm

https://eventpulse24.com/events/0191f3c2-…-7a41

The slug, never the id. /events/{uuid} is the signed-in Detail Screen — a friend who opened it would meet a sign-in wall instead of the event.

No query parameter, no fragment, no ?shared_by=. A variant would be a second URL for one document, and the public page canonicalises to /events/{slug} — a crawler fetching the variant would record two documents.

Why the link is worth receiving

The destination is FR-26's public page, which carries its Open Graph metadata — title, description and image — so the unfurl is rich in a messaging app, and a "Save to Pulse →" CTA so a recipient with no account has somewhere to go.

The description falls back to "{title} — {source}" when the event has none, so an unfurl is never a blank-bodied card. The image is static and branded, the same for every event.

! Three rules a mockup alone would lose read before implementing

The confirmation is not a toast

It is a bare aria-live="polite" region, never a second role="status". The digest page owns the page's status region and the Detail Screen's action row owns one for the conflict failure; two on a surface makes "which one is the page talking?" unanswerable by the DOM.

It is always present in the DOM, even when it says nothing — a live region added together with its text is not announced reliably.

A visible label, never an icon alone

There is no icon library in this product (DESIGN.md: "UI system: None"), and a share glyph with no label would fail the rule every other control here passes.

The accessible name is "Share {event title}" and contains the visible word "Share" (WCAG 2.5.3). On a digest of three cards, three buttons all named "Share" would tell a screen-reader user nothing about which event they are about to send.
