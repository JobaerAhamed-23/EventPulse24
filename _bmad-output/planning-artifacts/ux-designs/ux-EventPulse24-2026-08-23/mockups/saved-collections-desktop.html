Component states

Below the fold of the real surface: the four states of component.collection.header and component.emptystate.locked that cannot be shown simultaneously on a live page. This block is a spec demonstration and is not page chrome.

state 1 · rename (inline, no modal)

Clicking the collection name, or choosing Rename from ⋯, swaps the heading for an input at the same 26px display size so the line does not reflow. Enter commits, Esc reverts, blur commits. Duplicate names are permitted — the product does not correct a user's own filing vocabulary.

Enter to save · Esc to cancel

state 2 · delete confirm (inline row, no modal)

Deleting a collection never deletes saves — its events move to Unsorted. Because nothing is destroyed, this is an inline confirm row rather than component.modal.account-delete's type-to-confirm gate, which would overstate the stakes and risk a second overlay level (banned). Wrapped in role="alertdialog" with focus moved to Delete.

Delete “Music this month”? Its 2 events move to Unsorted.

state 3 · empty surface (no CTA)

Supersedes the prior orphan spine copy, which read “Single primary CTA pulses to the home” — that contradicted §5 No-CTA Discipline, a locked product principle. The sentence describing where saves come from does the navigational work a button would, without pushing.

Nothing saved yet.

Save an event from Pulse Digest or Browse and it lands here.

state 4 · free tier (component.emptystate.locked)

A Free user sees their saves ungrouped, then this locked Collections zone. Mirrors the locked-rows treatment component.control.day-picker already ships on /settings/quiet-hours, so the product has exactly one way of showing a Free user what tier value looks like. Deliberately not component.card.pro.upsell — that tinted gradient stays sanctioned on /digest and /settings → Plan only.
