E What the gate covers — and what it deliberately does not a lapsed user keeps what they have

Six operations, two gated

Create a collectionPro Add a save into onePro Read / openevery tier Renameevery tier Reorderevery tier Remove a save from oneevery tier Delete a collectionevery tier

Only the two operations that add are gated. A lapsed Pro user keeps using what they have, at its current size. Locking the surface entirely would make a downgrade destroy access to the user's own data.

Reorder is buttons, not drag

Move up / move down. Keyboard-operable with no pointer, needs no library, and needs no motion — the product has exactly one transition and styles/motion.test.ts fails the suite on any other animation.

The ends are disabled rather than silently inert, so the boundary is announced rather than discovered.

Each press sends the whole ordering in one request, so the server never observes a partially reordered list. A “put this one third” instruction would have to be interpreted against a list that may have changed since the client read it.
