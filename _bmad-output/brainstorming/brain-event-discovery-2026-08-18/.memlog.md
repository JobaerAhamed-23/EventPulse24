- (technique) started SCAMPER — Substitute lens on AI extraction layer
- (idea by user) Substitute AI extraction with schema-first JSON-LD (Schema.org Event) parser; LLM only as fallback for pages lacking structured data. ~80-90% LLM cost cut, no confidence scoring needed on structured data, moderation queue shrinks.
- (idea by coach) Schema-first is also dedup-first: Schema.org @id URIs dedup cross-listing-site duplicates (Eventbrite URL == organizer URL often). Free cross-source dedup.
- (idea by coach) Source reliability becomes observable cheaply with schema-first (track @validFrom / startDate changes) — feeds Source.reliability_score in PRD §9.6.
- (idea by coach) Schema-first enables publish-back: if EventPulse24 also emits Schema.org Event, Google Events / Alexa / other sites ingest events for free. Distribution channel from being a structured-data citizen.
- (risk) Spoofed/incorrect Schema.org blocks — structured data can lie about page content; need structured-data confidence score distinct from LLM confidence.
- (risk) Long-tail risk: sites WITHOUT JSON-LD may be exactly niche/unique-event sources (community meetups). Schema-first optimizes for known-event coverage, not new-event discovery.
- (risk) Schema drift: vendors (Eventbrite, gov portals) change markup; replaces LLM-extraction maintenance with parse-failure maintenance. Net win, not zero-cost.
- (idea by coach) Combine: keep schema-first pipeline + add tier-2 'diff crawler' — cheap LLM only on pages where JSON-LD hasn't changed in 30+ days (stagnant data = drift/fake signal). Drift detection, not extraction.
